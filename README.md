# 列表清理 · List Cleaner

**简体中文** | [English](README.en.md)

精简 Android 的分享、打开方式、深度链接、文件选择和其他系统入口，让常用应用排在前面；也可以通过 Root 管理应用提供的桌面图标、磁贴、快捷方式创建入口和桌面小部件。

## 使用要求

- Android 12 或更高版本。
- **规则过滤与优先排序**：需要支持 **modern libxposed API 102** 的框架，启用模块并配置作用域。传统 Xposed API 或仅支持较旧 API 的框架不适用。
- **组件管理**：需要在 KernelSU、Magisk 等管理器中为“列表清理”授予 Root 权限。仅启用 LSPosed 模块不等于授予 Root；查看组件列表不需要 Root。

包名为 `com.yagay.ListCleaner`。中文环境显示“列表清理”，其他语言显示“List Cleaner”。

## 功能介绍

### 规则：决定系统入口里显示哪些应用

规则页统一管理分享、多文件分享、发送到、打开方式、浏览器、深度链接、拨号、选择内容、拍照、录像、录音、文本处理，以及由 system_server 支持的**长按快捷方式**和 **Storage Access Framework 存储位置**等入口。**浏览器**和**深度链接**为独立分类：浏览器对应通用网页候选；深度链接可按域名分别管理 App Link 候选，并继承本分类的通用规则。支持搜索、应用展开及分类/状态筛选。

Android 11+ 的 Direct Share（联系人/会话建议）会跟随普通分享清理：当某个应用从分享候选中隐藏时，它的 Direct Share 目标也会同步过滤。List Cleaner 不读取或保存联系人、会话内容。

“长按快捷方式”结合系统 Hook 的运行时观察与只读主动扫描，后者以已启用的 Manifest/Dynamic Shortcut 为主，不保证发现所有固定或缓存项；“存储位置”管理 DocumentsUI 中的第三方存储根目录。两者只过滤对应系统候选，**不禁用应用组件，也不删除 Shortcut 或文件**。

| 显示模式 | 勾选的作用 |
| --- | --- |
| 隐藏选中 | 从相应系统候选列表中隐藏勾选项 |
| 只显示选中 | 只保留勾选项；该分类没有选中规则时显示全部 |
| 全部显示 | 暂停过滤，保留已保存的选择 |

**应用行的勾选针对当前分类、当前搜索条件下显示的组件**，不是禁用整个应用。展开应用后，可以单独选择某个组件；清理某一分类不会自动清理其他分类。已配置但暂时无法扫描到的项仍可在“已选规则”中取消。

应用或组件行右侧的**三点菜单**提供加锁/解锁，**长按对应行**也会打开操作菜单；不再通过左右滑动加锁。整体锁保护应用，部分锁保护子项，锁定会让全选/反选跳过该项，也会禁止锁定子项直接勾选；需要修改时应先解锁。未锁定不显示锁标记；锁不改变已选/半选/未选状态或优先顺序，“全部 → 已锁定”汇总各分类的锁定项。

规则、排序和组件列表共用应用类型与状态筛选，可按全部、用户应用、系统应用、已选、未选、已锁定等条件查看；选中分类与过滤条件通过主题色高亮。筛选只影响当前显示与批量操作范围，**不更改已保存规则、排序、批量锁或 Root 组件状态**。已更新的预装系统应用仍归为系统应用。

普通 Resolver 规则调整系统返回的候选列表，不卸载应用，也不修改组件的启用状态。长按快捷方式和存储位置使用独立的 system_server 查询过滤；未知/OEM 返回结构采用 fail-open，避免因无法识别数据而误删系统结果。

“包可见性兼容”只用于普通 Resolver 类别。长按快捷方式和存储 Provider 被明确排除，选择它们不会让所属应用对其他调用方整包不可见。

### 排序：让常用应用优先出现

各规则分类分别保存应用优先顺序；深度链接可按域名单独排序，未设置专属顺序时继承该分类通用顺序。长按快捷方式和存储位置也支持应用级排序，排序不会修改系统组件启用状态。

- 勾选应用即可加入优先列表，并移动到对应位置；取消勾选后回到未优先应用的默认名称顺序。
- 已优先应用按保存的顺序排在前面，未优先应用按名称排列；可筛选全部、未优先、已优先或已锁定，并可再按用户应用/系统应用缩小范围。应用类型筛选和锁定都不会移动应用或改写已保存的排序位置。
- **按住已优先应用右侧拖动手柄**再拖动调整顺序，靠近列表边缘自动滚动；长按应用行本身打开三点菜单。展开后仍可使用上移、下移。
- 搜索时只调整匹配的优先应用，未显示的配置保留原位置。被规则隐藏的候选不会显示在当前排序列表，其已保存顺序仍会保留。

规则勾选和优先排序是**待应用更改**：选择后先在底部点击“应用”并确认，或选择放弃。未确认的更改不会直接发布到运行时。

模块在已适配的系统查询和选择器排序环节应用优先顺序。厂商定制选择器、应用自行重排或自建菜单可能有不同表现。

### 组件：管理桌面图标、磁贴、快捷方式创建入口和小部件

“组件”页读取系统实际状态，支持搜索、禁用状态筛选，以及用户应用/系统应用独立查看和批量管理。

| 分类 | 支持范围 |
| --- | --- |
| 桌面图标 | 应用导出的 `ACTION_MAIN + CATEGORY_LAUNCHER` Activity / Activity Alias |
| 磁贴 | 应用提供的标准 `TileService`；不包含没有独立服务的 Wi-Fi、蓝牙等系统内置磁贴 |
| 快捷方式 | Android `LauncherApps` 注册的快捷方式配置 Activity + 旧 `ACTION_CREATE_SHORTCUT` 创建入口；真正的静态/动态/固定 Shortcut 在“规则 → 长按快捷方式”中以非破坏方式过滤 |
| 小部件 | 优先读取 `AppWidgetManager` 当前注册的 Provider，并合并 Manifest 小部件接收器作为兼容补充 |

| 设备控制 | 应用提供的 `ControlsProviderService`；实际禁用可能影响系统设备控制入口 |
| 账户认证器 | `AccountAuthenticator` 服务；禁用可能影响账户添加、恢复或同步 |

组件发现采用“**标准 API 优先、旧方式补充、异常自动降级**”的策略。同一个组件可记录多个发现来源并自动去重；诊断包会记录 `PACKAGE_MANAGER`、`APP_WIDGET_MANAGER`、`LAUNCHER_APPS` 等来源，方便判断漏项发生在哪一层。应用安装、更新或卸载后会自动使候选缓存失效，避免长期显示旧列表。

新版还加入组件发现运行时能力握手。若 APK 已更新但 system_server 仍运行旧 Hook，List Cleaner 不会强行调用新发现路径：Widget 会自动退回 Manifest 扫描；LauncherApps 或 Widget 注册表调用出现异常时也会 fail-open，保留旧扫描结果而不是让组件页或应用崩溃。重启并加载新版 Hook 后，确认支持新协议才重新启用完整的 AppWidgetManager 发现。

**勾选表示待提交的目标禁用状态，取消勾选表示待明确启用**，不是恢复此前的默认状态。先点击底部“应用更改”并确认，才会执行 Root 操作并回读系统结果；未授权或授权等待超时时会提示处理方法，不会显示虚假的成功勾选。

组件也使用三点菜单或长按行加锁/解锁，并提供已锁定筛选。应用展开与选中组件沿用主题高亮，未选组件不额外上色。**Root 禁用状态与批量锁不同**：锁与 Root 禁用无关，锁定的子项不能直接勾选，需先解锁；部分锁只针对对应子项。

Root 真禁用仍是组件管理的主机制。List Cleaner 会同时保存“应保持禁用”的组件策略，并通过 LSPosed/system_server 增加第二层发现结果过滤：即使系统或厂商服务在启动过程中短暂恢复组件，桌面图标、磁贴、快捷方式创建入口和小部件发现列表仍会继续过滤这些受保护组件。List Cleaner 自身查询会旁路过滤，以便继续管理和恢复它们。

开机后会自动校正持久禁用状态：`BOOT_COMPLETED` 和用户解锁后各执行一次延迟检查，并在启动稳定后再复查；应用安装/更新后也会触发校正。校正只处理“策略要求禁用、但系统实际已恢复”的组件，已保持 `DISABLED` 的组件不会重复执行 Root 命令。

检测到多个 Android 用户空间后，可通过顶部空间选择器切换目标。规则、优先排序、组件状态与批量锁按用户空间隔离；组件操作作用于**当前选中的空间**，受 Root/系统权限限制。系统核心组件、SystemUI、本应用及所属应用整体停用的组件只展示、不允许操作。

禁用会影响使用该组件的位置，包括桌面入口、已添加的磁贴或小部件；重新启用不保证恢复原位置。清除本应用数据或卸载模块**不会撤销系统中的组件禁用状态**，需要在卸载前按需启用。

### 备份与诊断

- 支持 **v13 多空间 JSON 备份**：可选择导出哪些空间，导入时逐项映射来源与目标空间；兼容读取旧版 v1–v12 规则备份。规则、显示模式与优先排序配置可随备份导入导出。
- 多空间备份可选附带 Root 禁用组件**参考清单**，但导入**不会执行 Root 命令，也不会自动恢复真实禁用状态或保护策略**；常用分类顺序、外观与列表默认偏好也不属于规则备份。卸载前应根据需要手动重新启用组件。
- 在**控制**主页顶部查看“模块状态”与同步摘要，点击进入**设置 → 清理与兼容**查看作用域和兼容详情；在**设置 → 高级与诊断**导出诊断 ZIP、查看运行时日志，分享前检查应用列表和日志。

### 控制：清理方式、分类开关与常用分类

底部 **控制（Controls）** 汇总模块状态、清理概况、快捷入口、常用分类与清理管理。快捷入口的 **Entry / Component** 对应“清理”页内部的两个编辑器，诊断入口进入设置；**Open** 是入口分类，而 **Root** 是组件操作机制，不是导航名称。

- **清理管理 → 入口清理**：列表首项为**默认清理方式**（隐藏已选、只显示已选、全部显示）。Entry 分类可以继承默认方式或单独覆盖；旁边的**启用/禁用清理**开关与清理方式相互独立。
- **清理管理 → 组件清理**：分别启用或禁用组件分类的清理功能。分类开关**不会立即禁用 Android 系统组件**，也不会自动恢复以前通过 Root 禁用的组件。两组支持搜索、状态筛选、全部启用/全部禁用，并在确认后保存。
- **常用分类**：点击标题旁的 **+** 可从 Entry 和 Component 中多选添加；列表图标和选中样式与“清理”页一致。长按常用项可移除或拖动调整混合顺序，默认只显示前四项，可展开全部。点击常用项直达对应分类。置顶及主页混合顺序是本地 UI 偏好，不属于规则备份。
- **受管理的入口分类**：Settings Apps（设置应用列表）与 Notification Channels（通知频道）位于 Entry/LSPosed 一侧，使用系统展示过滤，不是 Root 组件禁用。

### 界面与设置

Material 3 扁平化列表统一应用行、组件详情、分类筛选和三点菜单。底部导航为**控制、清理、设置**（Controls / Cleanup / Settings）；**清理**内部通过 Entry / Component 切换规则与 Root 组件管理，支持的 Entry 分类可通过排序图标打开优先级排序。展开的应用与选中组件使用主题色高亮；底部导航不额外绘制选中横线。

设置包含**外观与主题、列表与显示、扫描与刷新、清理与兼容、备份与恢复、高级与诊断**及**关于**。可配置明暗主题、界面尺寸、列表和刷新策略；“关于”展示版本、GitHub 和 [Telegram](https://t.me/LISTCLEANER) 链接。

## 开始使用

1. 从 [Releases](https://github.com/yagay/ListCleaner/releases/latest) 下载并安装正式版 APK。
2. 在支持 API 102 的模块管理器中启用“列表清理”，按推荐配置系统和实际选择器作用域，按框架提示重启。
3. 在**控制**主页查看模块状态，点击进入兼容/作用域详情；在**控制 → 清理管理 → 入口清理**选择默认清理方式、分类覆盖或启用/禁用，并确认保存。
4. 在底部**清理 → Entry** 选择分类并编辑规则；支持排序的分类用排序图标进入优先排序、拖动调整并确认应用。
5. 在**清理 → Component** 使用 Root 管理桌面图标、磁贴、快捷方式创建入口、小部件、设备控制和账户认证器。长按快捷方式和存储位置仍通过 LSPosed 候选过滤，不需要禁用组件。

组件管理独立于规则显示模式。Root 负责真实组件禁用，LSPosed 的 system_server 层负责防恢复与发现结果过滤；无需把每个第三方应用加入模块作用域。系统或厂商缓存仍可能需要关闭菜单后重新打开。

## 常见问题

**勾选组件后没有变化？**
先检查 Root 管理器是否允许本应用使用 `su`，再根据应用提示重试。LSPosed 授权与 Root 授权是两回事。组件列表以系统回读结果为准。

**某个应用或入口没有出现在列表？**
不同 Intent、应用可见性、Launcher 权限、DocumentsUI 缓存和厂商实现会影响扫描结果。自建分享面板、应用私有 Shortcut 和不规范声明的组件不一定受支持。显式指定目标的调用也不等同于系统候选菜单。

**更新测试版后新入口没有生效？**
长按快捷方式和存储位置新增了 system_server Hook。旧 Hook 无法凭空获得新的入口模块，因此测试新版 APK 后需要按模块管理器提示重启，让新的 Hook generation 加载。

**更新时提示签名冲突？**
正式版应使用同一发布签名覆盖升级。Debug 使用调试签名，可能无法覆盖正式版或其他构建机生成的 Debug。需要卸载前请先导出规则，并检查是否要恢复已禁用的组件。

### 排序支持与系统 Hook

排序仅对有对应运行时消费路径的入口分类开放。排序图标在不支持的分类中显示灰色，但仍可点击查看“当前列表不支持排序”的提示。**支持编辑不等于系统最终界面一定遵守优先级**：系统分享面板、桌面、角色选择器和厂商界面可能再次排序。

- **存储位置 / Document Root**：复用 DocumentsUI 根目录查询与最终侧栏 Hook，仅在能够识别的位置按保存的优先级调整顺序；保留系统行、分隔项及多用户位置。不同厂商 DocumentsUI 可能不兼容。
- **屏保 / Dream**：尝试在 Settings 的 `DreamBackend.getDreamInfos()` 返回候选时按应用优先级排序；不更改默认屏保或启用状态。类或方法不存在时跳过。
- **Document Provider、Photo Source、Notification Listener、Wallpaper**：尚无经过确认的最终界面排序路径，暂不开放排序。旧 Launcher Shortcut 类型已废弃。

每个 Android 用户空间独立保存规则和排序；新空间默认采用“隐藏已选”，默认应用类型筛选为“全部应用”（可切换用户/系统应用）。旧备份的排序配置不因界面可用性调整而删除。实际生效以目标系统选择器为准；CI 通过不代表设备适配验证通过。
